# Codex testing and research protocol

Timothy established this instruction on 2026-10-21. It applies to all test work in this repository.

Before running any exploratory test, diagnostic, benchmark, regression suite, or triggering CI tests, publish a pre-test entry in this repository's Issues or Discussions. Include the relevant discussion with Timothy, identified problem, hypothesis/proposed solution, expected and disconfirming results, tested branch/commit, method, data references, and bounds. A coherent suite may share one entry. Publish material plan changes before running the affected tests.

After execution, add a narrative follow-up in the same thread: what actually ran, observations, actual results including failures/unsupported cases, deviations, evidence and reproduction links, limitations, interpretation and next steps. Record blocked or interrupted runs honestly. Do not backdate plans for earlier tests or equate execution success with comprehension or learning.

When moving repositories, use the destination repository's issue/discussion section and cross-link related work. Keep private source text and credentials out of public posts. Progression reports and artifacts supplement, rather than replace, these threads. If posting is unavailable, report the blockage and prepare the plan locally; do not run dependent tests before publication unless Timothy explicitly authorizes an exception. Documentation-only work does not require artificial tests.
